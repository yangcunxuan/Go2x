# 熟悉项目的学习步骤

目标不是一次看完所有源码，而是沿真实数据流逐层理解。建议按以下顺序，每一步都做一个小验证。

## 第 1 步：只看页面和数据文件

1. 打开巡逻网页，依次看设备总览、三维建图、导航控制、地图管理、巡查点和积木任务。
2. 打开以下 JSON，观察页面数据从哪里来：
   - `patrol_data/config.json`
   - `patrol_data/active_map.json`
   - `patrol_data/checkpoints.json`
   - `patrol_data/tasks.json`
   - `runtime/robot_state.json`
   - `runtime/go2_state.json`
3. 只读观察一次狗趴下和站立前后 `body_height`、温度、姿态如何变化。

完成标准：能解释“长期数据在 patrol_data，临时状态在 runtime”。

## 第 2 步：理解网页前后端

阅读顺序：

1. `patrol_web/static/index.html`：页面有哪些区域。
2. `patrol_web/static/app.js`：页面如何请求 API、画点云和路线。
3. `patrol_web/server.py`：API、服务启动、安全检查、任务执行。

建议用浏览器开发者工具 Network 面板观察：

- `/api/status`
- `/api/cloud`
- `/api/navigation/path`
- `/api/maps`
- `/api/checkpoints`

完成标准：能从一个按钮追到对应 API，再追到写入的 JSON 或启动脚本。

## 第 3 步：理解容器和 ROS 工作区

阅读：

1. `Dockerfile`
2. `docker-compose.yml`
3. `docker/entrypoint.sh`
4. `scripts/build.sh`
5. `ros2_ws/src/patrol_bridge/setup.py`

练习：进入临时容器，执行 `ros2 pkg list`、`ros2 topic list`，不启动硬件动作。

完成标准：知道源码、build、install 的区别，知道改 ROS Python 包后何时需要 colcon build；知道 `scripts/nav_motion_bridge.py` 当前由导航脚本直接运行。

## 第 4 步：只理解 MID360 驱动

阅读：

- `config/MID360S_config.json`
- `scripts/run_driver.sh`
- `config/cyclonedds.xml`

观察：

- `/livox/lidar`
- `/livox/imu`

完成标准：知道雷达 IP、主机 IP、UDP 端口、ROS_DOMAIN_ID 和有线网卡为什么必须一致。

## 第 5 步：理解 FAST-LIO 建图和坐标系

阅读：

- `config/fastlio_mid360.yaml`
- `scripts/run_mapping.sh`
- `scripts/inside_mid360_mapping.sh`
- `ros2_ws/src/patrol_bridge/patrol_bridge/bridge.py`

重点理解：

- `livox_frame`、`camera_init`、`map_level`、`body`。
- `/Odometry` 与 `/Laser_map`。
- 雷达机械倾角补偿。
- `localization_alignment.json` 的用途。
- FAST-LIO 连续定位与全局重定位的区别。

练习：狗不动时记录 30 秒 XYZ/yaw，检查漂移和点云更新频率。

## 第 6 步：理解地图保存与 Nav2 导航层

阅读：

- `scripts/pcd_to_nav_map.py`
- `patrol_data/maps/patrol_3d_20260828_0922.meta.json`
- 对应的 `.yaml` 和 `.pgm`

用图像查看器打开 PGM，用点云工具/RViz 打开 PCD，对照它们的区别。

完成标准：能解释为什么三维 PCD 仍需要投影导航层，以及 PGM 的 resolution/origin 如何映射到地图坐标。

## 第 7 步：理解 Nav2

阅读：

1. `scripts/inside_navigation.sh`
2. `config/nav2_mid360.yaml`
3. `config/navigate_to_pose_no_recovery.xml`

按数据顺序理解：

```text
/scan -> costmap -> Navfn /plan -> DWB /cmd_vel
```

练习（狗必须趴下、运动租约关闭）：启动导航服务但不下发目标，查看 Nav2 节点、生命周期、地图和 `/scan`。

完成标准：能区分全局规划器、局部控制器、全局代价地图、局部代价地图和行为树。

## 第 8 步：理解 GO2 控制与安全联锁

阅读：

- `scripts/nav_motion_bridge.py`
- `ros2_ws/src/patrol_bridge/patrol_bridge/go2_state_bridge.py`
- `patrol_web/server.py` 中 `teleop_command`、`require_go2_motion_safe`、导航 API。

重点：

- `/cmd_vel` 和 Unitree Sport Move 的参数差异。
- ROS 域 42 与域 0 如何通过 JSON 中继。
- 命令时效、站立高度、温度、定位和路线起点保护。
- 为什么失败必须发送停止并自动趴下。

练习：狗趴下，只观察准备生成的指令文件，不允许实际运动；再在安全空旷场地做 0.5 米单轴动作。

## 第 9 步：理解 C12

阅读：

- `c12_web/server.py`
- `c12_web/presets.json`
- 桌面 `启动C12双光控制.sh`

按顺序理解 RTSP 取流、FFmpeg 转换、UDP 云台协议、预置点和调色板回读。

## 第 10 步：理解巡逻任务

阅读 `app.js` 中 Blockly block 定义、`compileChain`，再读 `server.py` 中任务保存和 `execute_steps`。

先建立“等待 + 调色板 + 截图”的无运动任务，再加入一个近距离导航点。

## 推荐的修改流程

1. 修改前记录当前服务和硬件状态。
2. 只改一个层：前端、Web API、ROS 桥或 Nav2 配置。
3. 先做语法检查/单元式数据检查。
4. 狗趴下验证话题、路线和输出指令。
5. 空旷、安全、低温时做短距离实机验证。
6. 对比日志与 XYZ 是否符合现场。
7. 大改动再更新桌面项目记录。

不要直接在 `build/` 或 `install/` 中改代码；改 `ros2_ws/src/`、`scripts/`、`config/`、`patrol_web/` 或 `c12_web/` 的源文件。
