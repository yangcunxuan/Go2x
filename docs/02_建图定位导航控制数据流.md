# 建图、定位、导航与控制数据流

## 1. MID360 三维建图与定位

```text
MID360S 192.168.123.170
  │ Livox UDP 点云/IMU
  ▼
livox_ros_driver2
  ├── /livox/lidar
  └── /livox/imu
        │
        ▼
FAST-LIO2 (fastlio_mapping)
  ├── /Odometry                 实时位姿
  ├── /cloud_registered         当前配准点云
  ├── /cloud_registered_body    机身坐标点云
  ├── /Laser_map                累计三维地图
  └── /path                     轨迹
        │
        ├── patrol_bridge ──> runtime/robot_state.json
        └── patrol_cloud_bridge ──> runtime/cloud_bridge/cloud.json
                                      └── 巡逻网页三维显示
```

入口：

- 宿主机：`scripts/run_mid360_nav_mapping_stack.sh`
- 容器内：`scripts/inside_mid360_mapping.sh`
- 雷达：`scripts/run_driver.sh`
- FAST-LIO：`scripts/run_mapping.sh`
- 参数：`config/MID360S_config.json`、`config/fastlio_mid360.yaml`

`map_level -> camera_init` 静态 TF 用于修正 MID360 机械倾斜，并通过 `runtime/localization_alignment.json` 对齐保存地图坐标。

## 2. 保存地图

网页保存地图时：

```text
/Laser_map
  ▼
patrol_cloud_bridge 保存请求
  ▼
patrol_data/maps/<地图名>.pcd        三维原始地图
  ▼
scripts/pcd_to_nav_map.py
  ├── <地图名>.pgm                   二维导航占据层
  ├── <地图名>.yaml                  Nav2 map_server 配置
  └── <地图名>.meta.json             会话、坐标系、对齐信息
```

当前活动地图由 `patrol_data/active_map.json` 指定。

## 3. Nav2 路线规划

```text
保存的 PGM/YAML
  ▼
nav2_map_server
  ▼
global_costmap（静态层 + MID360 实时障碍层 + 膨胀层）
  ▼
NavfnPlanner / A*
  ▼
/plan ─────────────────────────────> runtime/nav_path.json ──> 网页青色路线
  ▼
DWBLocalPlanner + local_costmap
  ▼
/cmd_vel
```

入口：

- 宿主机：`scripts/run_navigation_stack.sh`
- 容器内：`scripts/inside_navigation.sh`
- Nav2 参数：`config/nav2_mid360.yaml`
- 行为树：`config/navigate_to_pose_no_recovery.xml`

全局规划目前是平面规划。点位虽然保存 XYZ，但 Nav2 主要使用 X/Y；Z 用于显示和地图一致性检查。

## 4. 实时障碍

```text

  ▼

  ├── global_costmap 动态障碍层
```

## 5. GO2 控制链路

```text
Nav2 /cmd_vel
  ▼
scripts/nav_motion_bridge.py          ROS_DOMAIN_ID=42
  ├── 路线起点误差检查
  ├── 点云/定位新鲜度检查
  ├── 站立、电机温度检查
  ├── 单轴执行（前进或侧移，禁止斜向同时走）
  └── runtime/go2_nav_command.json
          │ 文件中继，跨 DDS 域
          ▼
go2_state_bridge.py                   ROS_DOMAIN_ID=0
  ├── /api/sport/request              Unitree Sport API
  ├── GO2 LowState/SportState
  └── runtime/go2_state.json
```

主要 Unitree Sport API：

- `1003`：StopMove/停止。
- `1004`：StandUp/站立。
- `1005`：StandDown/趴下。
- `1008`：Move，参数 `{"x": 前后, "y": 左右, "z": 旋转}`。

当前 GO2 固件对纯 `z` 原地旋转没有可靠响应；前进和左右侧移已验证能执行。因此导航桥现阶段把 DWB 的复合速度拆成单轴动作。

## 6. 网页手动控制

```text
网页按键/API
  ▼
patrol_web/server.py
  ▼
runtime/go2_nav_command.json
  ▼
go2_state_bridge
  ▼
GO2 Sport API
```

键位：

```text
U  I  O       左前 / 前进 / 右前
J  K  L       左移 / 停止 / 右移
M  ,  .       左后 / 后退 / 右后
Q     E       左转 / 右转（当前纯旋转可能不生效）
```

按住连续发送，松开立即发送停止。自主导航运行时网页手动控制会被拒绝，避免两套控制互相覆盖。

## 7. C12 双光链路

```text
C12 192.168.144.108
  ├── RTSP 554 /stream=1 可见光
  ├── RTSP 555 /stream=2 热成像
  └── UDP 5000 云台/姿态/调色板
        ▼
c12_web/server.py (127.0.0.1:8088)
  ├── 双路 MJPEG 网页预览
  ├── 八方向持续云台控制
  ├── 预置点保存与调用
  └── 白热/铁红/彩虹/红热/黑热等调色板
```

摄氏度温度数据需要 C12 的测温 SDK/私有协议或带辐射测温的码流元数据，当前尚未实现。

## 8. Blockly 巡逻任务

前端将积木编译成 JSON 步骤，保存到 `patrol_data/tasks.json`。当前步骤类型：

- 导航到巡查点。
- 等待。
- 切换热成像调色板。
- 调用 C12 预置点。
- 保存双光截图。
- 重复若干次。

执行器在 `patrol_web/server.py` 的任务线程中顺序运行这些步骤。
