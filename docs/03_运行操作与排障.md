# 运行操作与排障

## 最简单的使用方式

Ubuntu 桌面双击：

- `GO2X智能巡逻系统.desktop`：打开 `http://127.0.0.1:8090`。
- `C12双光预览与云台控制.desktop`：打开 `http://127.0.0.1:8088`。
- `启动MID360S建图.desktop`：旧式的驱动 + FAST-LIO + RViz 双终端入口。

巡逻网页中的“开始三维建图”“启动导航”“停止导航”等按钮会调用后端 API 并管理服务。

## 命令行启动

```bash
cd /home/byl/go2_mid360_stack

# 构建镜像与 ROS 工作区
docker-compose build
docker-compose run --rm ros2 ./scripts/build.sh
docker-compose run --rm ros2 ./scripts/verify.sh

# MID360 + FAST-LIO 三维建图/定位
./scripts/run_mid360_nav_mapping_stack.sh

# GO2 状态桥（域 0）
./scripts/run_go2_state_bridge.sh

# Nav2（通常由网页启动）
./scripts/run_navigation_stack.sh

# 巡逻网页
python3 patrol_web/server.py

# C12 网页
python3 c12_web/server.py
```

不要重复启动同一服务。网页后端使用 `runtime/service_*.json` 记录持久服务 PID 和状态。

## 正常操作顺序

### 建图

1. 检查 GO2、MID360、Ubuntu 电源稳定。
2. 检查有线网口为 `192.168.123.10/24`。
3. `ping 192.168.123.170` 和 `ping 192.168.123.161`。
4. 打开巡逻网页，点击“开始三维建图”。
5. 确认点云持续更新、XYZ 连续、方向箭头正确。
6. 控制狗缓慢走完整区域，避免快速搬动雷达。
7. 点击保存地图，填写稳定的地图名。
8. 确认 `patrol_data/maps/` 同时出现 PCD、PGM、YAML、meta.json。

### 创建巡查点

1. 在正确活动地图中查看三维点云。
2. 地图选点或记录狗当前位置。
3. 检查 XYZ 和朝向。
4. 保存巡查点；数据在 `patrol_data/checkpoints.json`。

### 导航

1. 先确认狗的实际位置和网页位置一致。
2. 确认狗的箭头方向与现场一致。
3. 确认活动地图正确、FAST-LIO 点云和 `/Odometry` 在线。
4. 确认当前位置位于可通行区域。
5. 点击启动导航并等待 Nav2 激活。
6. 让狗站立，再点击巡查点“导航到此”。
7. 检查青色路线起点贴合狗当前位置。
8. Ubuntu 播报“导航已启动”后才表示真实运动命令已发出。
9. 播报“导航失败”时运动已切断并应自动趴下。

## 停止方法

- 网页点击“停止导航”。
- 网页手动控制按 `K` 或松开当前按键。
- 终端前台运行的脚本按 `Ctrl+C`。
- 紧急情况下使用遥控器/机器狗急停手段，不依赖网页。

## 日志在哪里

| 问题 | 首先查看 |
|---|---|
| MID360 无数据 | `runtime/logs/livox_driver.log` |
| FAST-LIO 无位姿/发散 | `runtime/logs/fastlio.log`、`runtime/logs/patrol_bridge.log` |
| 大点云中断 | `runtime/logs/patrol_cloud_bridge.log` |
| 导航启动/规划失败 | `runtime/logs/nav2.log`、`runtime/logs/navigation.log` |
| 点云转障碍异常 | `runtime/logs/mid360_nav_cloud_to_scan.log` |
| GO2 不执行 | `runtime/logs/go2_state.log`、`runtime/go2_state.json` |
| 运动桥拒绝 | `runtime/logs/nav_motion_bridge.log`、`runtime/nav_motion_enable.json` |
| 巡逻网页 | `runtime/logs/patrol_web.log` 或 `patrol_web/logs/patrol_web.log` |
| C12 | `c12_web/logs/c12_web.log` |

## 常见问题判断

### 雷达可 ping，但点云停了

可能是 Livox 驱动数据流挂起。先看 `/livox/lidar` 频率和驱动日志，不要直接认为是 IP 问题。重启建图会产生新的 FAST-LIO 起始坐标，必须重新定位/对齐保存地图后才能导航。

### Wi-Fi 断开

Wi-Fi 只用于 SSH/远程网页；MID360 和 GO2 数据走 `192.168.123.0/24` 有线网。正确配置下 Wi-Fi 断开不应影响建图、控制和离线巡逻。

### 搬动趴着的狗后位置错误

FAST-LIO 是连续里程计，不是自动全局重定位器。直接搬动会触发位姿突变保护，或让当前位置与保存地图错位。需要扫描匹配/ICP、人工初始位姿或正式的全局重定位模块，不能直接导航。

### Docker 权限

当前用户应属于 `docker` 组。执行 `groups` 检查；新加入 docker 组后需要重新登录或重启会话。

### 机器狗瘫软

先停止运动并读取 `runtime/go2_state.json` 的电量、电压、电机最高温度和模式。此前出现过电机过热和供电不稳；不要反复站立验证软件。
