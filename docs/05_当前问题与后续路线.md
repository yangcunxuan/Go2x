# 当前问题与后续路线

## P0：导航前必须解决

### 1. 近场假障碍

现场确认狗前方无障碍，但 `/scan` 持续出现约 `0.40 m` 最近点。原始点云检查发现相应点高度约 `0.04 m`，疑似机身、线缆或地面回波。

当前已经尝试调整 `pointcloud_to_laserscan` 的 `min_height`，但还没有完全消除。下一步应：

1. 在狗站立和趴下两种姿态记录 `/cloud_registered_body`。
2. 确认 `body` 原点和 XYZ 轴。
3. 按几何区域建立自车遮罩，而不是仅调大 `range_min`。
4. 保留真实 0.5 米障碍，再重新测试左/右绕行。

在该问题解决前，不能宣称自主导航完成。

### 2. 正式全局重定位

当前 FAST-LIO 重启后主要依靠静态对齐和一次离线 ICP/现场信息恢复坐标，不是自动生产级重定位。应接入：

- 基于保存 PCD 的 scan matching/ICP/NDT 初始定位；或
- 支持地图加载与定位模式的 LiDAR SLAM；或
- FAST-LIO + `hdl_global_localization`/同类全局定位组件。

必须输出配准置信度；置信度不足时禁止导航。

### 3. GO2 旋转控制

纯 `Move(x=0,y=0,z)` 在当前 GO2 固件上没有可靠原地转向，网页前后左右可工作。需要核对：

- Unitree 固件运动模式和遥控器 Start 状态。
- Sport API 的 Move/TrajectoryFollow 或 SDK 版本。
- 是否需要先切换 gait/mode。

在解决前，导航只能用前进和侧移近似跟随路线。

## P1：巡逻可靠性

1. 将导航、建图、GO2 桥和网页做成 systemd 用户服务，替代松散 nohup/PID 文件。
2. 加入自动健康监控：雷达频率、Odometry、点云年龄、GO2 状态、电量、温度和网络。
3. 导航结束后明确区分 succeeded/failed/canceled，并保留每次任务报告。
4. 记录实际轨迹与规划路线，计算横向误差、到点误差和耗时。
5. 增加悬崖/台阶/负障碍检测；单纯 LaserScan 不足以保护四足机器人。
6. 对 Orin NX 做 arm64 镜像构建、功耗、温度和启动时间测试。

## P1：地图管理

1. 地图版本、创建时间、设备外参、会话 ID、校准版本需要统一元数据。
2. “续建”目前不能真正恢复 FAST-LIO 滤波器状态，应在页面明确限制。
3. 删除、归档、导出地图要有独立 API 和确认流程。
4. 巡查点必须强绑定地图版本，地图变更后提示重新检查。

## P2：C12

1. 接入辐射测温/温度矩阵，显示摄氏度、中心温、最高温和测温框。
2. 将 C12 相机位姿标定到 `body`，让巡查点照片与地图位置关联。
3. 任务中加入温度阈值告警、录像和异常截图。

## P2：深度/视觉避障

MID360 能提供三维几何，但对玻璃、近距离盲区、悬崖和低矮负障碍可能不足。后续深度相机应：

- 固定到 GO2 机身并标定到 `body`。
- 输出深度点云/障碍层。
- 与 MID360 融合到体素或高程地图。
- 在 Orin NX 上运行视觉/语义检测。

单目相机可做语义识别和光流，但没有额外模型/尺度来源时不能作为可靠的近场深度安全传感器。

## 建议验收指标

### 建图

- 连续 30 分钟点云不掉线。
- Wi-Fi 断开不影响有线建图。
- 闭环区域墙体重影在可接受范围。
- 重启后可自动重定位且给出置信度。

### 导航

- 10 次 3–10 米到点成功率至少 90%。
- 到点 XY 误差小于 0.25 米。
- 0.5 米前方障碍能选择净空更大一侧绕过。
- 无障碍时不出现自车假障碍。
- 规划失败后 0.5 秒内停止运动。

### 控制与安全

- 松开网页按键后 0.3 秒内停止。
- 点云、定位、GO2 状态任一过期后立即停止。
- 电机温度达到阈值禁止站立/导航。
- 导航失败自动播报并趴下。

### C12

- 双路预览连续 1 小时稳定。
- 云台按住连续、松开停止。
- 预置点重复调用误差可接受。
- 调色板回读与实际显示一致。
